# Перевірка ігрового етапу

Дата: 8 листопада 2026.

## Автоматичні перевірки

- npm.cmd run typecheck — успішно.
- npm.cmd run build — успішно; PixiJS-поле завантажується окремим модулем.
- npm.cmd test — 5 тестів пройшли: точна кількість і площа, детермінована генерація, зворотні спільні контури, володіння, з’єднання і завершення.
- npm.cmd run test:rooms — 2 інтеграційні тести пройшли з реальними клієнтами Colyseus: два гравці, відмова третьому, блокування чужого руху, передавання руху/прив’язування, повернення з токеном; запуск 1/1000/3000 і відхилення 0/3001/дробового числа.

## Перевірка у браузері

- Кімната на 1000 деталей відкрилась із полем PixiJS.
- Пазл з однієї деталі перетягнуто мишею до рамки: прогрес змінився на 100%, з’явилося повідомлення завершення.
- Кімната на 3000 деталей відкрилась із canvas; помилок/попереджень у перевіреній консолі не було.
- Друга вкладка приєдналась до тієї самої кімнати на 1000 деталей; обидва гравці відображаються.
- Показ зразка, кнопки масштабу та повернення всього столу доступні й спрацювали.
- Оновлення першої вкладки зберегло кімнату та роль «Гравець 1».
- Другу тестову вкладку закрито, щоб звільнити місце.

Це перевірка функціональності на поточному ПК, а не гарантія FPS на всіх пристроях. Гру через інтернет і довготривале збереження в PostgreSQL ще не перевіряли й не реалізовували.

## Чіткість під час масштабування

Виправлено розтягування початкового атласу: SharpPieceTextures повторно раструє видимі фрагменти поточної SVG-картини в роздільності, достатній для масштабу камери та render resolution. Рамки деталей і зображення генеруються з векторного джерела. Велика одиночна деталь обробляється лише в межах видимого фрагмента з буфером; збільшений атлас усіх 3000 деталей не створюється.

Кеш обмежений 20 мегапікселями активних текстур. Заміна джерел перебудовує батчі через публічний API PixiJS; старі джерела видаляються після двох кадрів. При зміні видимого фрагмента зберігається повна базова деталь до готовності нового фрагмента. Обробка виконується до чотирьох зображень паралельно.

Перевірки:
- 3 тести detail-policy.test.mjs: достатня щільність пікселів, обрізання великої деталі, покриття після зміщення.
- Команда: node --experimental-strip-types --test apps/client/tests/detail-policy.test.mjs.
- typecheck і build пройшли в тимчасовій копії коду, щоб watcher не перезапустив активні серверні кімнати.
- У браузері перевірено повторні цикли fit/zoom-in/zoom-out на 1000 деталях, сильне наближення на 3000 та великий фрагмент на 1 деталі, перетягування після зміни якості. У свіжій тестовій вкладці консоль не містила помилок або попереджень.
- Перевірки стосуються поточного векторного джерела quiet-bay.svg. Це не вимірювання FPS або гарантія якості довільних майбутніх растрових фотографій.


## Згладжування загального вигляду

Додано GroupSurfaceTextures: з’єднані деталі малюються суцільним зображенням із одним складеним nonzero-контуром. Це прибирає незалежне змішування напівпрозорих країв і дрібні щілини на внутрішніх стиках. Оригінальні спрайти залишаються інтерактивними з alpha=0, тому захоплення та рух групи працюють через наявні правила.

Додано mipmap-фільтрацію базового атласу та суцільних груп і згладжування кадру з щільністю не нижче 2. Лінії стиків у групі приглушені, а коли деталі на екрані менші за 10px, внутрішні лінії приховуються, щоб не створювати шум. Роздільність окремих деталей при наближенні визначається реальною щільністю екрана, а не додатковим згладжуванням кадру: це не створює зайвих сотень текстур на проміжному масштабі.

Перевірено:
- Суцільна рухома група із 6 деталей: загальний масштаб, видимі стики, перетягування, збільшення та повернення назад.
- Поле на 3000 деталей: загальний вигляд, перехід до робочого та максимального масштабу й повернення назад; фінальна браузерна перевірка без помилок/попереджень.
- 3 тести політики роздільності та 5 тестів геометрії/правил пройшли.
- Фінальні typecheck і build пройшли в тимчасовій копії; активний сервер не перезапускався.

# Домашня мережа — 2026-11-08

- Start-LAN тепер показує та копіює повне запрошення на активну кімнату. Після створення кімнати через localhost тестовий launcher надрукував `http://10.0.0.57:5174/?room=fYW4iVqPH`, а clip.exe завершився успішно. Повторний запуск використовує чинний сервер та продовжує стежити за кімнатою.
- Адаптер клієнта повідомляє локальний Vite про активну кімнату раз на 20 секунд; localhost:5173 передає повідомлення LAN-клієнту на 5174. Вихід прибирає запис, записи закритих вкладок спливають через 70 секунд. Читання ID кімнати з LAN-адреси відхилено 403; launcher читає лише через loopback.

- Виправлено localhost-запрошення: Vite `/api/lan-origin` підтверджує активний LAN proxy і повідомляє адресу поточного приватного IPv4 інтерфейсу. Адаптер кімнати використовує її для запрошень з loopback; посилання зі звичайної мережевої адреси зберігають свій origin.
- Браузерна перевірка: створено 1000 деталей через localhost:5173, запрошення отримало `10.0.0.57:5174`, друга сесія успішно ввійшла через нього. Копіювання на HTTP підтверджено станом «Посилання скопійовано». Typecheck/build та 2 інтеграційні тести через LAN proxy пройшли повторно.

- Перевірено LAN-запуск (`npm.cmd run dev:lan`): клієнт слухає TCP 5174 на мережевих інтерфейсах; сервер кімнат залишається на loopback 3001 через HTTP/WebSocket proxy. Активний сервер повторно використовується.
- Поточна Wi-Fi адреса: `10.0.0.57`; HTTP `/api/health` через `http://10.0.0.57:5174` повернув `status: ok`.
- Windows Firewall: `WebPazle-Home-LAN`, Node.js, TCP 5174, джерело LocalSubnet, профілі Private/Public (поточний Wi-Fi має Public). Правило підтверджено після адміністративного запуску.
- Дві браузерні сесії через Wi-Fi адресу успішно приєдналися до кімнати на 1000 деталей. Перевірка виконана на цьому ПК; фізичного другого пристрою в агента немає.
- Інтеграційні тести з `TEST_ENDPOINT=ws://10.0.0.57:5174/realtime`: 2/2 PASS — синхронізація руху, власність, третій гравець, reconnect, кількості 1/1000/3000 і відхилення некоректних значень.
- Typecheck і build пройшли в тимчасовій копії, щоб не перезапускати активний сервер. TypeScript-скрипт запуску окремо перевірено `tsc --noEmit --strict`.

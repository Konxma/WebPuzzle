# WebPuzzle для наступного чату

Спільний пазл для трьох гравців у браузерах в одній локальній мережі. Кімната має рівно від 1 до 3000 деталей, типове значення — 1000. Вхід за посиланням `?room=ID` або кодом кімнати. Можна грати самому або запросити до двох гравців за QR-кодом.

## Стек

| Частина | Технології та роль |
| --- | --- |
| Проєкт | TypeScript, Node.js 22, npm workspaces. Спільний пакет `@web-pazle/shared` збирається перед клієнтом і сервером. |
| Клієнт | React 19 і Vite 8 для екранів. PixiJS 8 для поля, камери, текстур і перетягування. Іконки `@gentleface/react`. |
| Сервер | Node.js, Colyseus 0.18 і `@colyseus/ws-transport`. HTTP для входу в кімнату, WebSocket для гри. |
| Дані | Активні кімнати в пам’яті. Автозбереження JSON і фото JPEG у `.data` на ПК господаря. PostgreSQL для запуску не потрібен. |

Клієнт побудований за MVVM. React викликає команди ViewModel, ViewModel працює через інтерфейс `RoomGateway`, а реалізація на Colyseus підставляється в `App.tsx`. Правила гри живуть у спільному пакеті. Сервер вирішує, кому належить група і чи можна її з’єднати або зафіксувати в рамці.

Після входу клієнт підписується на повідомлення і надсилає `sync`. Сервер відповідає `snapshot`, з якого клієнт відновлює контури за кількістю деталей і seed. `motion` змінює положення однієї групи. `delta` передає зміну власника, об’єднання, фіксацію або перенесення в лоток. PixiJS оновлює поле поза React і малює кадр на запит. При обриві сервер звільняє захоплені деталі та тримає місце гравця до 60 секунд. Перезапуск закриває кімнати, збережені пазли можна відкрити знову.

`PuzzleRoom` записує стан під час створення та після завершеної дії. Ключ збереження передається тільки творцю кімнати й запам’ятовується у `localStorage` для поточної адреси гри. Він не входить до посилання запрошення. При відновленні `PuzzleEngine` відбудовує членство деталей у групах і скидає блокування від попередніх сеансів. Перевірка `npm.cmd run test:saves` запускає окремий сервер із тимчасовою папкою, зупиняє його й перевіряє відновлення.

Лоток є частиною серверного стану групи. Вибір лотка та «Лише краї» діють тільки на перегляд поточного клієнта. `PuzzlePhotos` нормалізує обране фото до JPEG, сервер зберігає його за випадковим ID. `PuzzleArtwork` використовує одне декодоване фото для атласу й видимих фрагментів при наближенні.

### Чіткість поля

Canvas має фізичну роздільність екрана. `displayDensity.ts` відстежує зміну DPR, зокрема перенесення вікна між моніторами Windows без зміни розміру вікна. Тема змінює тільки кольори фону й рамки.

`detailPolicy.ts` задає два пікселі текстури на фізичний піксель екрана. Здалеку `PuzzleRenderer` перемальовує один спільний атлас з оригіналу під поточний масштаб. Це зберігає пакетне малювання 1000–3000 деталей. Старий атлас 1x із mipmap-фільтрацією пом'якшував дрібні контури. Зблизька `SharpPieceTextures` і `GroupSurfaceTextures` готують тільки видимі фрагменти з запасом для переміщення. Фільтр linear працює з текстурою достатньої роздільності, без nearest-пікселізації або повторного mipmap-розмиття. Ліміт розміру великого фрагмента зменшує надлишкову роздільність, а не скасовує уточнення повністю. Якість вихідного фото залишається межею його деталізації.

Оновлення текстур обмежене за частотою, але не відкладається нескінченно через рух миші чи мережеві події. Завершений фрагмент приймається, якщо його масштаб і покриття ще актуальні. Нерухоме поле не малює зайві кадри.

Перевірки `node --test apps/client/tests/*.test.mjs` охоплюють роздільність, великі фрагменти, зміну DPR і планування кадрів. Для перевірки справжнього WebGL відкрийте `/tests/rendering.html?debugRender` через Vite та натисніть `Run rendering checks` після завершення збірки. Стенд без сервера кімнат перевіряє 1, 997, 1000 і 3000 деталей, змодельовані DPR 1/1.25/2, безперервні події руху, зібрану групу та нерухомий стіл. Стенд не змінює збережені ігри й не входить у production-збірку.

Право видаляти гостя належить власнику кімнати. `PuzzleRoom` перевіряє відправника `kick-player`, звільняє місце гостя та скасовує його поточну можливість перепідключення. При остаточному виході власника роль переходить до гравця, який залишився. Тема зберігається локально в браузері. Згортання панелі й повноекранний режим керують розміром області PixiJS через `ResizeObserver`.

## Як запустити й перевірити

- Двічі натиснути `Start.cmd`. Він відкриває гру для локальної мережі на порту `5174` і використовує активний сервер кімнат або запускає свій на `127.0.0.1:3001`.
- `npm.cmd run dev` запускає розробку на `127.0.0.1:5173`. Vite пересилає `/api` та `/realtime` до сервера кімнат. `/api/lan-origin` допомагає знайти адресу `5174`, коли браузер відкрито через localhost. `/api/lan-invite` передає активне запрошення у вікно запуску.
- Після зміни коду виконати `npm.cmd run typecheck`, `npm.cmd run build` і `npm.cmd test`. Для перевірки мережі запустити сервер і виконати `npm.cmd run test:rooms`. Щоб пройти тим самим проксі, що й браузер, встановити `$env:TEST_ENDPOINT='ws://127.0.0.1:5174/realtime'` перед тестом.
- При зміні правил перевірити точну кількість деталей, у тому числі 1, 997, 1000 і 3000. При зміні мережі перевірити трьох гравців, відмову четвертому та повернення зі збереженим прогресом. Дві вкладки на одному ПК перевіряють синхронізацію, а окремий пристрій у LAN додатково перевіряє доступ через мережу.
